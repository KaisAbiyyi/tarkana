# First-Run Dashboard CTA Repair Design

## Goal

Repair the blank-looking primary CTA in the first-run dashboard without redesigning the dashboard or changing its data and routing behavior.

## Confirmed Scope

- Preserve the header, first-run hero, mode selector, selected state, feature preview, fonts, palette, borders, first-run condition, and challenge route.
- Diagnose the rendered CTA before changing it, including computed styles, DOM content, interaction states, pseudo-elements, and animation-owned inline styles.
- Keep one selected-mode source of truth for the selected radio card, selected-mode text, CTA label, and `mode` query parameter.
- Verify all four modes: Pola Angka, Pola Simbol, Deduksi Singkat, and Memori Pola.

## Implementation Design

Add an `ink` variant to the shared `Button` primitive. The variant owns the CTA's resting visual contract: near-black background, explicit yellow text, black border, and short hard shadow. The first-run CTA will use this variant instead of combining the default primary variant with conflicting local background and text utility classes.

Render the CTA label as real child text inside the anchor generated by `Button`. No pseudo-element, overlay, clipping, opacity animation, or GSAP timeline will control label visibility. The anchor remains the correct semantic element because the action navigates to the challenge route.

The CTA will remain full width. Its minimum height and padding will be reduced modestly from the current oversized large-button treatment while retaining a target of at least 44 by 44 pixels. Spacing between metadata, button, and panel edge will use the existing 8-pixel rhythm. Existing dashboard layout and copy remain unchanged.

## State Contract

- Default: black background, explicit yellow text, visible label, short hard shadow.
- Hover: slight upward movement; label color and visibility unchanged.
- Active: button moves toward the shadow; label remains visible.
- Focus-visible: global high-contrast focus outline remains visible; label remains visible.
- Disabled/loading: not used by this navigation CTA. Existing primitive semantics remain intact for other consumers.
- JavaScript failure: server-rendered anchor and label remain visible and usable.

## Diagnosis and Safety Checks

Browser inspection will record `background-color`, `color`, `opacity`, `visibility`, `display`, `transform`, `clip-path`, `mix-blend-mode`, `text-indent`, `font-size`, `line-height`, and `z-index`. It will also inspect `::before`, `::after`, inline styles, DOM text, and element bounds in default, hover, active, and focus-visible states.

The audit will explicitly confirm whether the current blank appearance comes from utility-class cascade conflict, an overlay, a pseudo-element, or animation state. Implementation will follow the observed cause rather than assumption.

## Testing and Visual QA

Add focused Playwright coverage for:

- visible default label and accessible name;
- computed foreground/background contrast contract;
- label updates and matching `mode` URL for all four modes;
- hover, active, and focus-visible visibility;
- no horizontal overflow or clipped CTA at 320, 375, 390, 430, 768, 1024, 1280, 1366, 1440, and 1920 pixels;
- preserved selected radio state and non-interactive status badge.

Capture before and after screenshots for representative desktop and mobile viewports. Run type check, lint, unit tests, E2E tests, and production build.

## Non-Goals

- No dashboard redesign.
- No copy, font, palette, header, feature-preview, first-run logic, backend, authentication, challenge configuration, or route changes.
- No new animation or UI library.
- No unrelated refactor.
